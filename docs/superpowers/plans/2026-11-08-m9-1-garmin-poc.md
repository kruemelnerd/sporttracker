# M9.1 Garmin Personal API Proof of Concept Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Document the verified Garmin Personal API capabilities and provide an isolated, local-only PoC without changing production import/sync behavior.

**Architecture:** Keep the PoC as an opt-in command-line tool, separate from Spring services and scheduled jobs. Read credentials only from the environment, use documented Garmin endpoints, and keep API responses/activity files in an ignored local directory. Reuse the existing FIT decoder for downloaded files without routing them through production import or persistence.

**Tech Stack:** Python standard library for HTTPS and local response capture; existing Java 25/Garmin FIT SDK 21.221.0 decoder for FIT inspection; Markdown research report.

**Spec:** User request M9.1 in this conversation; final report `docs/research/m9.1-garmin-poc.md`.

## Global Constraints

- No production Garmin sync, scheduler, database migration, or production FIT/import/Intervals.icu changes.
- Never request credentials in chat, log keys/tokens, or commit API responses, FIT, GPS, or personal activity data.
- Use only Garmin's documented Personal API and distinguish documented features from live-tested results.
- If credentials are unavailable, report live testing as BLOCKED; do not substitute mocks.
- Preserve existing checkout changes; work only on `feat/m9-1-garmin-poc` based on `origin/main`.

## Review Focus

- Missing/empty API key and rejected credentials must fail without printing secrets; verify via a local no-network test.
- HTTP/API error bodies and headers may contain sensitive data; capture only safe status/metadata and a sanitized error summary.
- API responses or downloaded ZIP/FIT files must never land in tracked paths; verify ignored output location and repository status.
- Malformed JSON, unexpected ZIP contents, and non-FIT files must be reported without entering production import or persistence.
- Live activity fields, Garmin rate limits, historical retention, and mutation behavior remain unverified unless real API access is available.
