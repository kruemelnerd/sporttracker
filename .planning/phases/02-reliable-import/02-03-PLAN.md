<interfaces>
Plan 02 establishes `POST /api/imports` as multipart `files[]` returning `ImportBatchResponse { outcomes, batchError? }`. Each outcome has original file name, one of `IMPORTED|DUPLICATE|SKIPPED_NON_RUN|INVALID|FAILED`, a safe message, and optional activity id; `batchError` carries `BATCH_COUNT_EXCEEDED` or `REQUEST_TOO_LARGE` plus a safe actionable message and no per-file outcomes. Map this transport response in `frontend/src/api.ts`; browser `File` objects stay inside the view queue.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User file picker/drop zone → queue | Browser files and names are untrusted; client validation is only a usability aid. |
| Typed upload client → local API | Outcome payloads are transport input and must not become unsafe rendered content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08 | Tampering | frontend upload queue | medium | mitigate | Keep browser file association by private queue id, submit through typed multipart API, and let the backend enforce content limits. |
| T-02-09 | Information disclosure | rendered import outcomes/browser smoke | medium | mitigate | Render safe API messages as text, avoid filesystem/parser/GPS detail, and assert local-only network use. |
| T-02-10 | Denial of service | repeated retry controls | low | accept | The local UI permits user-initiated retries; backend count/size limits and per-file transactions bound each request. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; use the existing Vue, Vitest, and Playwright toolchain. |
</threat_model>
