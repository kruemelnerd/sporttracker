# Plan 01: Local Foundation

## Goal

Create the independently buildable backend/frontend skeleton and reproducible PostgreSQL/Flyway local foundation without implementing FIT import behavior.

## Tasks

### 1. Bootstrap the backend build

- Create `backend/` as a Gradle Kotlin DSL project using Java 21 and the selected compatible Spring Boot patch. Check in `gradlew`, `gradlew.bat`, and `gradle/wrapper/**` and verify the wrapper version.
- Add only the Phase-1 dependencies: Web MVC, validation if needed by the endpoint contract, PostgreSQL runtime, Flyway plus its PostgreSQL module, and test support. The Garmin SDK dependency is added and owned by Plan 02.
- Add the application entry point and local configuration with environment overrides for database URL, credentials, server port, display timezone, and configurable data directory.
- Add a minimal health response or actuator-free startup check that does not create a public product endpoint beyond what the smoke test needs.

**Verification:** `./gradlew build` from `backend/` succeeds on a clean dependency cache; application context starts with the test profile.

### 2. Add Compose PostgreSQL and Flyway baseline

- Create `compose.yaml` with PostgreSQL, safe development defaults, a named data volume, port override, and a healthcheck.
- Add the first Flyway migration under the backend resources with only the minimal foundation schema or connectivity marker required by the project; explicitly avoid Phase-2 activity/record/lap persistence.
- Configure Spring to wait for and migrate the Compose database on startup.
- Ensure credentials are supplied by environment or `.env.example`, never committed as secrets, and make reset destructive only through an explicit documented command.

**Verification:** `docker compose config` succeeds; `docker compose up -d db` reaches healthy; backend startup completes Flyway migration; a second startup reports the migration as already applied.

### 3. Bootstrap the frontend and proxy

- Create `frontend/` with Vue 3, TypeScript, Vite, and Vue Router using the native npm build setup.
- Add a minimal route shell with a summary route placeholder and a typed API module boundary, without dashboard/import/detail features.
- Configure Vite to proxy `/api` to the Spring Boot port using an environment override for the target when useful.
- Add frontend scripts for `typecheck`, `build`, and `test:unit` using Vitest and Vue Test Utils; `npm run test:unit` is the exact frontend test command.

**Verification:** `npm ci` and `npm run build` from `frontend/` succeed; the dev server proxies an `/api` request to the backend without direct cross-origin configuration.

### 4. Document the local path

- Create `README.md` with prerequisites, Compose start/health/stop/reset commands, backend start, frontend start, ports, and the Phase-1 boundary. Plan 03 owns the final smoke-command section.
- State that FIT fixtures are committed and tests do not download private or external activity data.

**Verification:** follow the documented commands from a clean checkout and reach running DB, backend, and frontend processes.

## Exit Criteria

- Backend and frontend build independently.
- PostgreSQL is persistent through a named volume and Flyway runs from a clean database.
- No Phase-2 import/persistence behavior or unrelated product code is present.
