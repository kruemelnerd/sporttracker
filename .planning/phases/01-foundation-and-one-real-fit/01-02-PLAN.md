# Plan 02: Real FIT Decode Slice

## Goal

Prove that the pinned Garmin FIT SDK decodes one committed Garmin sample into a small internal model and a typed REST response.

## Tasks

### 1. Add and document the real fixture

- Obtain one Garmin-provided sample FIT through the documented source before implementation and commit it under `backend/src/test/resources/fit/`.
- Record source, license/redistribution note if applicable, filename, and SHA-256 in a fixture README or test documentation.
- Keep fixture loading classpath-based and offline; do not download during tests or copy it into PostgreSQL.
- Record the exact Garmin source URL and redistribution note in the fixture documentation when the sample is selected. Phase 1 intentionally commits only this real sample; incomplete/sensorless and malformed fixture coverage remains Phase 2.

**Verification:** a fixture integrity test computes the expected SHA-256 and fails clearly if the binary is missing or altered.

### 2. Implement the minimal SDK adapter and internal model

- Pin the Garmin FIT Java SDK version in `backend/build.gradle.kts` and compile a small adapter using the version's actual decoder API. Verify the dependency resolves through the checked-in Gradle wrapper.
- Decode the fixture's relevant messages into an internal summary object: running sport, start timestamp, distance, status, and non-empty record/lap indicators or bounded counts.
- Keep SDK message classes inside the adapter. Preserve nullable values and convert FIT time to `Instant`; do not add persistence entities or a general import service.
- Define behavior for absent optional messages as `null`/empty rather than fabricated zeroes.

**Verification:** backend tests decode the fixture successfully and assert semantic values, plausible timestamp/distance, running sport, and non-empty decoded record/lap structures without exact full-payload snapshots.

### 3. Expose the typed decode endpoint

- Add the read-only `GET /api/fixture-summary` controller/service endpoint that reads the classpath fixture and returns an explicit DTO with stable JSON field names for sport, start time, distance, status, and the bounded record/lap proof.
- Add predictable error handling for a missing/undecodable fixture without returning stack traces, absolute paths, or Garmin SDK internals.
- Keep the endpoint read-only and fixture-specific; do not accept multipart files or persist activities in this phase.

**Verification:** MockMvc or an equivalent HTTP test asserts status, content type, typed fields, UTC timestamp representation, and the expected successful decode status.

## Exit Criteria

- A real committed FIT is decoded by the official SDK through an adapter.
- The response is a small typed API contract and does not expose FIT SDK or JPA classes.
- Phase-2 upload, duplicate, normalization, and persistence behavior remains absent.
