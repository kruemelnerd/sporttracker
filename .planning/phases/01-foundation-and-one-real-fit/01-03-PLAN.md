# Plan 03: Vue Summary and Smoke Gate

## Goal

Connect the frontend to the decode endpoint through the Vite proxy and provide an automated local smoke proof for the complete Phase-1 path.

## Tasks

### 1. Implement the typed summary route

- Define a frontend TypeScript DTO matching the minimal backend JSON response explicitly; do not share Java classes or SDK types.
- Make the summary route fetch `/api/fixture-summary` through the Vite proxy and render sport, formatted start time, distance, decode status, and the record/lap proof.
- Add loading and understandable error states, but no upload controls, dashboard aggregation, maps, charts, or detail navigation.
- Keep formatting at the UI boundary while retaining numeric/API semantics.

**Verification:** `npm run test:unit` with Vitest confirms the response fields render and a failed API response produces a visible actionable error.

### 2. Add the local automated smoke verification

- Add Playwright with `frontend/playwright.config.ts` and `frontend/tests/e2e/phase1.spec.ts` as the browser/API smoke harness.
- Add `frontend/scripts/phase1-smoke.sh`, invoked from `frontend` as `./scripts/phase1-smoke.sh`, to run `docker compose up -d db`, wait for the `db` healthcheck, start backend via `../backend/gradlew bootRun` and frontend via `npm run dev -- --host 127.0.0.1`, then wait on `curl --fail http://127.0.0.1:8080/api/fixture-summary` and `curl --fail http://127.0.0.1:5173/`.
- The Playwright test asserts PostgreSQL/Flyway readiness through the API, that `GET /api/fixture-summary` returns the real fixture summary, and that the frontend summary route renders the same typed values through `/api`.
- After readiness checks, the script must run `npx playwright test` using `frontend/playwright.config.ts`; the script exits zero only when that suite passes.
- Trap process cleanup and leave the named database volume intact; only an explicit `docker compose down -v` may destroy it.

**Verification:** `cd frontend && ./scripts/phase1-smoke.sh` exits zero from a clean checkout after `npx playwright install --with-deps chromium`; failure output identifies DB, backend, proxy, or rendering stage.

### 3. Close the phase boundary

- Update README with the exact final Phase-1 command, `cd frontend && ./scripts/phase1-smoke.sh`, its one-time Playwright prerequisite, and expected observable values/shape without hard-coding brittle full FIT snapshots.
- Review the diff for accidental scope expansion: no file upload, normalized activity persistence, duplicate classification, six-week dashboard, maps, charts, or external analytics.

**Verification:** run `cd backend && ./gradlew test`, `cd frontend && npm run test:unit`, `cd frontend && npm run build`, and `cd frontend && ./scripts/phase1-smoke.sh`; all pass without downloading the FIT fixture.

## Exit Criteria

- A local automated test proves Compose DB availability, Flyway startup, real FIT decoding, typed REST response, Vite proxying, and Vue summary rendering.
- The implementation is ready for Phase 2 without requiring a root build orchestrator or changing the Phase-1 API boundary.
